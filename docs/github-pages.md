# GitHub publication

This export contains the published birthday site from source commit `132937c91e2fa68228317baa9d75fe03fbf03c8f`, with portable asset paths for a GitHub Pages project URL. Source HTML, CSS, dynamic photographs, chess pieces and the Stockfish Worker all use relative local URLs. Font and engine licenses are retained. No secrets or hosting credentials are included.

1. Once, in Settings > Pages, choose GitHub Actions as the publishing source. This repository setting requires a signed-in administrator; a pull request cannot enable it. The repository and account must support Pages.
2. Merge the publication pull request into `main`. The merge automatically builds, verifies and publishes the site.
3. If the merge happened before Pages was enabled, run the `Build and publish birthday gift` workflow from Actions after completing step 1.

Pull requests run the production build and the real Stockfish integration check without deploying. Pushes to `main` publish automatically, and manual publication remains available. No `PAGES_ENABLED` variable is needed.

The calendar opens on November 14. It is a birthday puzzle, not an access control. Letter drafts stay in the visitor's browser. Email delivery still depends on FormSubmit and recipient activation; it was not verified during this export.
